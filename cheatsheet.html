D1: エージェント型アーキテクチャとオーケストレーション (Agentic Architecture) 27%

必須暗記事項

  • 拡張LLM (Augmented LLM) = 脳 + ツール(手) + 検索(目) + メモリ(メモ帳)
  • ワークフロー: 開発者が手順定義（予測可能・安定・低コスト） / エージェント: LLMが自律判断（柔軟・予測不可能・高コスト）
  • Anthropic推奨: シンプルさ優先 — 不必要にエージェント化しない。段階的に複雑さを増やす
  • stop_reason: tool_use = ループ続行 / end_turn = 完了。テキスト内容ではなく必ずstop_reasonで判定

5つのワークフローパターン

  • Prompt Chaining — 順次処理+ゲート（例: 翻訳→品質チェック）
  • Routing — 入力分類と振り分け（例: カスタマーサポートの部門振り分け）
  • Parallelization — Sectioning（異なるサブタスク並行）/ Voting（同一タスク複数実行）
  • Orchestrator-Workers — 動的タスク分解・委任・統合（例: 複数ファイル修正）
  • Evaluator-Optimizer — 生成→評価→改善ループ（例: 文学翻訳の品質向上）

マルチエージェント

  • 通信方式: Message Passing（明示的送受信） / Shared State（共有メモリ） / Handoff（制御権譲渡）
  • Agent SDK連携: Agent-as-Tool（部分委任・呼び出し元が制御保持） / Handoff（完全制御権移譲）
  • タスク分解: Functional Decomposition（「何を」で分ける） / Data Decomposition（「何に」で分ける）
  • Coordinator-Subagent = Hub-and-spoke（車輪型）。独立コンテキスト、情報は明示的に提供

安全性設計

  • Guardrails: Input Guardrail（入力検証） / Output Guardrail（出力検証）
  • Human-in-the-loop: 読み取り→自動 / 書き込み→確認 / 不可逆→必ず承認
  • エージェントループ4段階: Gather Context → Take Action → Verify Work → Iterate
間違いやすい: Agent-as-Toolは「結果を統合して返す（部分委任）」、Handoffは「完全に制御権を渡す（担当交代）」。戻す定義がなければ戻らない。
D2: Claude Codeの設定とワークフロー 20%

必須暗記事項

  • 5つの権限モード: plan / default / acceptEdits / dontAsk / bypassPermissions
  • 権限評価順序: deny > ask > allow（denyが常に最優先）
  • 設定優先順位（強→弱）: Managed > CLI > local > project > user
  • 読み取り専用ツール: Read, Grep, Glob, Agent
  • 権限必要ツール: Write, Edit, Bash, WebFetch, WebSearch
  • サブエージェント3種: Explore(Haiku,読み取り専用), Plan(読み取り専用), General-purpose(全ツール)
  • サブエージェントはネスト不可（1階層のみ）

CLAUDE.md

  • 3層階層: ~/.claude/CLAUDE.md(個人) → PROJECT_ROOT/CLAUDE.md(チーム) → .claude/CLAUDE.md(個人local)
  • @import: 複数ファイルに分割管理（相対パス）
  • .claude/rules/: 条件付きルール（Always/Auto Attached/Manual）

Hooks

  • PreToolUse: exit code 2で実行阻止
  • PostToolUse / UserPromptSubmit / Stop / SessionStart

CI/CD統合

  • -pフラグ: 非対話モード（ヘッドレス）
  • --max-turns: 暴走防止 / --max-budget-usd: コスト制限（-p時のみ有効）
  • bypassPermissionsは隔離環境（コンテナ）でのみ使用
間違いやすい: bypassPermissionsでも.gitディレクトリへの書き込みは確認あり。MCP設定の優先は .mcp.json > ~/.claude.json（プロジェクトレベルが優先）。
D3: プロンプト工学と構造化出力 20%

必須暗記事項

  • ゴールデンルール:「最小限のコンテキストしか持たない同僚に混乱させない指示」
  • XMLタグ: Anthropic公式推奨（<instructions>, <context>, <example>, <input>）
  • Few-shot最適例数: 3〜5個。Relevance(関連性)とDiversity(多様性)を重視
  • 否定形ではなく推奨形で指示を書く

プロンプトキャッシング (Prompt Caching)

  • 入力コスト90%削減、レイテンシ85%削減
  • 有効期間: 5分（最終アクセスから）
  • 初回書き込み: 25%増加コスト
  • 最小キャッシュ: 1,024トークン

構造化出力

  • 制約付きデコーディング: 100%スキーマ準拠保証
  • 2方式: JSON Outputs（textに出力） / Strict Tool Use（inputフィールドに出力）
  • additionalProperties: false — 常に設定（必須）
  • 非サポート制約: minimum/maximum, minLength/maxLength, pattern, anyOf/oneOf/allOf, $ref
  • Strict Mode: "strict": true で100%準拠

システムプロンプト

  • APIのsystemパラメータで指定（messages配列ではない）
  • 長文: データを上部、質問を下部 → 品質30%向上
  • Lost in the Middle: 中央の情報は見落とされやすい。重要情報は先頭/末尾に配置
間違いやすい: JSON Schemaの型は8つ。minimum/maxLengthなどの数値制約はサポートされない。Pydantic(Python)とZod(TypeScript)でスキーマ自動生成可能。
D4: ツール設計とMCP統合 18%

Tool Use 4ステップ通信フロー

  • 1. 開発者がtools + message送信
  • 2. Claudeがtool_useブロック返却（stop_reason: "tool_use"）
  • 3. 開発者がツール実行、tool_result再送信
  • 4. Claudeが最終回答（stop_reason: "end_turn"）

必須暗記事項

  • ツール定義3要素: name, description(最重要), input_schema
  • tool_use_id: リクエスト-レスポンス紐付け（荷物追跡番号）
  • tool_choice 4モード: auto / any / tool(指定) / none
  • tool_resultは必須 — エラーでも返却が必要。is_error: trueでエラー認識
  • Claudeはツールを実行しない — 「どのツールを使うか」を判断。実行はクライアント側

MCP (Model Context Protocol)

  • M×N問題 → M+Nに削減
  • プロトコル: JSON-RPC 2.0ベース（Anthropic専用ではない）
  • 3つの役割: Host(アプリ) / Client(1:1接続) / Server(ツール提供)
  • トランスポート: stdio(ローカル) / Streamable HTTP(リモート)
  • 3プリミティブと制御主体:
  • Resources(読み取り) → アプリケーション制御
  • Tools(実行) → モデル(LLM)制御
  • Prompts(テンプレート) → ユーザー制御
  • Sampling: サーバーからLLMへの逆方向通信
間違いやすい: MCPはTool Useを置き換えない（補完関係）。MCPは「接続規格」、Tool Useは「呼び出し仕組み」。

キーコンセプト

  • 入力トークン（低コスト） vs 出力トークン（高コスト・入力の数倍）
  • チャンキング: 固定長(簡単・文脈断裂) / セマンティック(文脈保持・複雑) / オーバーラップ
  • RAG 3段階: Retrieval → Augmentation → Generation
  • Contextual Retrieval: Anthropic独自。チャンク+文脈説明で精度67%向上
  • 指数バックオフ: リトライ間隔を指数的に増加（1秒→2秒→4秒）

ハルシネーション対策

  • 明示指示 / コンテキスト限定 / 確信度表明 / Temperature制御 / 複数生成・比較 / RAG / 引用(Citations)

検証パターン

  • 出力スキーマ検証 / 2段階生成 / クロスチェック / ガードレール
  • Multi-pass Review: 同一セッションではなく別の独立セッションでの検証
間違いやすい: コンテキストウィンドウは「入力+出力」の合計が上限。プロンプトキャッシングの初回書き込みは25%増加コストがかかる。

試験当日のTips
  • 時間配分: 1問あたり約2分。迷ったらマークして先に進む。後半に時間を残す
  • シナリオ問題の読み方: まず「何が問われているか」（設計判断/実装方法/トラブル対応）を特定してから選択肢を見る
  • 「最も適切なもの」パターン: 正しい選択肢が複数ある場合、Anthropic推奨のベストプラクティス（シンプルさ優先、最小権限）を選ぶ
  • 消去法を活用: 明らかに間違いの選択肢を2つ消し、残り2つで判断する
  • キーワード注意:「常に(Always)」「決して(Never)」を含む選択肢は誤りであることが多い（例外がある場合）
  • Anthropicの哲学を意識: 「シンプルさ優先」「段階的に複雑さを増やす」「deny優先」「最小権限」が一貫したテーマ
